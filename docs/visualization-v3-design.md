# World Graph 可视化 V3 设计方案（从零重设计）

> **状态**: 设计文档，待评审
> **日期**: 2026-07-23
> **背景**: V2 版（LiteGraph.js 蓝图风画布）实战后被否——自由画布作为主编辑面对新手不友好、与"查询过滤+字段编辑"的核心需求错配。本文从零重设计。
> **约束**: 服务端 `/api` 契约不变（零改动）；仍要求无构建、离线可用、静态文件由 visualizer server 服务。

---

## 1. 需求复盘：用户到底是谁、要干什么

从 V2 实战反馈提炼：

- 用户是小说作者（非图数据库工程师），**新手**，对"节点画布"范式没有直觉
- 核心动作序列是：**按条件找到实体 → 看它当前状态 → 改字段 → 确认历史/影响**
- 次要动作：理解实体间关系（"师父和林墨什么关系"）、穿越时间（"ch-3 时世界什么样"）、角色视角（"林墨现在知道什么"）
- 数据规模：长篇小说也就几十~几百个实体、几百条声明——**不需要万节点画布性能**

结论：V2 选错了主范式。**图可视化是辅助理解手段，不是主编辑面**。主编辑面应该是表单/表格——这正是用户说的"查询过滤各种内容，然后手动编辑字段"。

## 2. 新范式：时间轴 + 三栏数据工作台

```
┌────────────────────────────────────────────────────────────────┐
│  ◄ ch-1 ──●───────●────●─────●───► ch-6        [帮助] [刷新]    │  ← storyTime 时间轴滑块（第一公民）
├──────────┬──────────────────────────────────┬──────────────────┤
│ 实体列表  │  中栏视图：[邻域图|全景图|快照表]  │   详 情 编 辑 器  │
│ ┌──────┐ │  ┌─ 邻域图：选中实体的一度关系图  │  ┌────────────┐ │
│ │搜索…  │ │  ├─ 全景图：全部实体+全部关系    │  │ 基本信息    │ │
│ └──────┘ │  └─ 快照表：全部实体×全部属性     │  │ 属性（表格） │ │
│ 类型筛选  │                                  │  │ 关系（表格） │ │
│ ●角色 ●地点│   （三个视图共享选中态：          │  │ 可见性      │ │
│ ●物品 ●概念│    左栏点选 → 图高亮/表定位；     │  │ 历史（时间线）│ │
│ ──────── │    图中点节点 → 右栏打开编辑）     │  └────────────┘ │
│ ▸ 林墨    │                                  │  [保存修改]      │
│ ▸ 赵无极† │                                  │                  │
│ ▸ 苏晚晴  │                                  │                  │
│ ▸ 青霜剑  │                                  │                  │
│ ▸ …      │                                  │                  │
└──────────┴──────────────────────────────────┴──────────────────┘
```

**三个区域各司其职**：

| 区域 | 职责 | 交互 |
|---|---|---|
| 顶部时间轴 | storyTime 的第一公民呈现 | 滑块拖动/点击刻度 → 全界面切换到该时刻快照；事件标记为刻度上的点 |
| 左栏 | 查找 | 搜索框（hybrid 检索）+ 类型筛选 + "含已消亡"开关；列表项显示类型色点+名称+摘要截断；点击选中 |
| 中栏 | 理解 | 三个可切换视图（见下）；纯导航，**不在图上编辑** |
| 右栏 | 编辑 | 分区表单：基本信息/属性/关系/可见性/历史，全部中文字段+说明，保存即提交 |

**中栏三视图（共享选中态，互相联动）**：

1. **邻域图（3D）**：选中实体的一度关系图（自己+直接关系对端），点击邻居→切换聚焦。理解"这个实体和谁有关"
2. **全景图（3D）**：当前 storyTime 全部实体+全部关系的 **三维力导关系图**（three.js 渲染：左键拖拽旋转、右键平移、滚轮缩放、悬停显示实体摘要 tooltip、点击节点→右栏打开编辑；类型着色；已闭合关系默认隐藏、开关可见）。理解"世界结构"——关系网、枢纽实体、孤立实体
3. **世界快照表**：当前 storyTime 全部实体 × 全部属性的完整表格，按实体分组，支持类型/模态筛选与关键词过滤。理解"全部实体的全部状态"——图放不下的完整状态在这里。点击行 → 右栏打开编辑并定位到对应属性

**3D 的纵深用法（可选增强，V3.1）**：第三维不只用于炫技——"时空模式"下把 Z 轴映射为 storyTime：实体按诞生时刻在深度上分层排布（近处是现在、深处是过去），关系按生效时间分布，消亡实体在对应深度淡出。这让双时态模型在空间里直观可见。默认仍是力导模式，时空模式作为切换项。

**事件链**改为独立页签里的**纵向时间线**（el-timeline）：每条事件一张卡片（时刻、类型、主角、增删声明数、source 着色），点击展开详情，不再是节点图。

**角色视角**：工具栏选角色后进入"视角模式"——左栏列表和中栏图只显示/高亮该角色可见的内容，不可见的属性在编辑器里置灰锁定。

## 3. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 应用框架 | **Vue 3**（global build，vendored 单文件 ~160KB） | 中文文档最完善；模板语法新手可读；组件化解决 V2 五个 500 行命令式 JS 文件的维护噩梦；无构建（`vue.global.prod.js`） |
| UI 组件库 | **Element Plus**（UMD full，vendored ~1MB） | 优雅的直接来源：专业的表单/表格/抽屉/时间轴/滑块组件，**默认中文 locale**，与 Vue 3 无构建搭配成熟 |
| 关系图 | **3d-force-graph**（UMD `dist/3d-force-graph.min.js`，vendored，内置 three.js + d3-force-3d） | 三维力导图的事实标准：API 极简（`Graph(elem).graphData({nodes,links})`）、内置旋转/缩放/悬停/点击交互、UMD 单文件免构建；邻域图与全景图共用同一组件 |
| 样式 | Element Plus 主题 + 少量自定义 CSS | 不再手写整套暗色主题（浅色主题对长时间编辑更友好，可选暗色） |

**否决项**：
- LiteGraph.js：维护停滞（2024-01）、原生 UI 英文、新手不友好——已实战验证不合适
- AntV G6 v5：优秀的 2D 图库（中文文档、主题现代），但**纯 2D**，与"中栏要 3D"的需求不符，降级为 2D 备选
- React Flow / xyflow：需要 React 生态 + 构建步骤，且同样面向 2D，违背无构建约束
- Cytoscape.js：偏图分析算法库，2D，UI 组件为零，编辑交互要全自研
- vis-network：2D，UMD 可用且更轻，但默认样式陈旧、中文资料少
- echarts-gl（graphGL）：支持 3D 力导图且有中文文档，但子项目多年未活跃更新，WebGL 兼容性不如 three.js 生态
- D3/three.js 自绘：违背"不从 0 造轮子"

**降级路径**：若 3d-force-graph 实战有问题（WebGL 兼容性/性能），中栏降级为 AntV G6 v5 2D 图；图渲染隔离在一个组件内（统一 props: nodes/links/选中态/事件回调），替换成本低。

## 4. 数据流与 API 映射（服务端零改动）

| 界面元素 | API |
|---|---|
| 时间轴刻度 | `GET /api/status`（storyTimes + 事件数） |
| 左栏列表 | `GET /api/graph?storyTime=&includeClosed=` |
| 搜索 | `GET /api/search?q=&storyTime=&type=` |
| 中栏邻域图 | 选中实体的 `/api/entities/:id` + `/api/entities/:id/history`（relations） |
| 中栏全景图/快照表 | `GET /api/graph?storyTime=&includeClosed=`（一次拉全量，前端渲染） |
| 属性/关系编辑 | `POST /api/events`（change，source=user）/ `POST /api/relations(/close)` |
| 可见性矩阵 | `GET /api/declarations/:id/visibility` + `POST /api/visibility(/close)` |
| 历史时间线 | `GET /api/entities/:id/history` |
| 事件时间线 | `GET /api/events` |
| 角色视角 | `GET /api/character-view?characterId=&storyTime=` |

## 5. 关键交互细节

**属性编辑（核心场景）**：右栏"属性"区是一张可编辑表格，列：属性名 | 值 | 模态（事实/信念/推测下拉）| 生效时间 | 操作（删除）。行内编辑，底部"+ 添加属性"。表头下常驻一行说明："每次保存生成一条 change 事件，旧值不会丢失，可在历史页查看"。点保存 → diff 出 invalidated/newFacts → `POST /api/events` → toast 成功并刷新。

**新手引导**：沿用 V2 中文化成果——所有字段带灰色说明小字；首次打开显示一次性的引导气泡（el-tour 或简单实现）介绍三个区域；帮助按钮常驻。

**空态**：每个区域独立空态文案（"暂无实体，点击右上角新建"、"该实体在此刻没有属性"等）。

**时间轴语义**：滑块停在 ch-N 时，整个工作台展示"ch-N 时刻的世界"。在此刻做的编辑，事件 storyTime 默认取**当前选中时刻的下一刻**（或弹窗确认），避免改写历史——这是一个需要评审确认的决策点。

## 7. 实施路径

1. vendor 三件套下载验证（vue / element-plus / 3d-force-graph UMD 可用性）
2. 骨架：Vue + Element Plus 接入，三栏布局 + 时间轴，打通 /api/status 与 /api/graph
3. 左栏列表 + 搜索/筛选；中栏三视图（邻域图 → 快照表 → 全景图，按此顺序实现）
4. 右栏详情编辑器（属性编辑为先，可见性/历史随后）
5. 事件时间线页签 + 角色视角模式
6. 新手引导 + 空态打磨；种子数据全场景人工验收
7. 验收通过后删除 V2 前端文件（graph-view.js / detail-panel.js / events-view.js / vendor/litegraph.*）

## 8. 明确不做

- 不做自由画布上的拖拽连线编辑（图只用于导航）
- 不做多分支对比、实时推送、撤销栈（同 V1 设计的 V3+ 远期项）
- 不改服务端 `/api` 契约

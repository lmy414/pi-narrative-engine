# 前端 Demo UI 高保真对齐设计规格

## 目标

以 `D:\claude\pi-ex\narrative-engine-design\pages` 的 8 个设计师 HTML 原型为视觉、信息架构和业务状态基准，重构 `frontend-demo` 的视图层；保留现有 Mock 数据、模拟 API、路由和业务状态，使 Demo 在不连接真实后端的情况下具备完整、可验证的前端交互。

## 验收标准

采用“高保真并优化”：

- 页面结构、尺寸、间距、字体、颜色、组件层级和业务状态尽量与原型一致。
- 不改变设计稿的核心导航、三栏工作区和业务专属组件。
- 可修复原型中的明显可用性问题，包括输入失焦、键盘焦点、窄窗口溢出、加载/空/错误/确认状态。
- 不接入真实后端，不修改后端代码，不引入 React/Vue 或构建步骤。

## 技术方向

继续使用静态 HTML、CSS 和原生 JavaScript SPA：

- `mock-data.js`：Demo 数据源。
- `api-mock.js`：后端接口模拟与错误信封。
- `app.js`：路由、全局 StoryTime、项目上下文和通用覆盖层。
- `views/*.js`：按业务视图拆分渲染和交互。
- `styles/*.css`：按设计令牌、壳层、通用组件和页面拆分样式。

## 全局壳层

项目管理使用独立启动器壳层。其他页面使用设计稿的顶部工作台导航：左侧品牌与项目，中间一级模块，右侧 StoryTime、搜索和辅助入口。删除当前左侧全局导航，页面横向空间交还给页面内部侧栏。

## 状态与数据流

- `App.activeProject` 控制项目门禁。
- `App.storyTime` 是跨页面唯一 StoryTime 来源。
- 页面状态按路由命名空间存放，避免共享平面状态污染。
- 所有业务读写经过 `apiCall`，纯展示状态留在页面状态内。
- Mock API 返回现有 `{ ok, data, error }` 信封，错误由统一通道处理。

## 交互与无障碍

- 可点击控件优先使用 `button`、`a`、`input` 等原生语义元素。
- 提供 `focus-visible`；Modal/Drawer 支持 Escape 关闭。
- 输入过程不触发整页重绘。
- 三栏页面只允许各区域内部滚动，不产生页面级横向溢出。
- 动画仅用于状态过渡，并尊重 `prefers-reduced-motion`。

## 验证

- JavaScript 文件逐一执行 `node --check`。
- 使用 Node 测试覆盖 StoryTime、筛选、事件因果、文件 dirty/冲突和设置状态等纯函数。
- 本地静态服务逐页浏览回归。
- 每个页面与对应设计稿并排检查结构、视觉层级和关键状态。

## 非目标

- 不连接真实后端。
- 不修改后端接口。
- 不实现生产级 3D 图引擎。
- 不引入框架或构建工具。
- 不新增设计稿之外的产品模块。

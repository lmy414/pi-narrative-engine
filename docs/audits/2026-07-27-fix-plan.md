### 4.1 P0-4 写入无事务/无回滚

**问题证据**：
- [commit.ts:100-163](../../packages/scheduler/src/commit.ts#L100) `for (const [entityId, changes] of changesByEntity)` 循环无 try/catch
- 第 N 个 entityId 失败时：前 N-1 个已写入 world-graph（脏数据）
- [commit.ts:190](../../packages/scheduler/src/commit.ts#L190) 步骤 8 `deletePlan(planId)` 不执行 → plan 残留缓存
- 调用方重试同 planId 会再次写入前 N-1 个（重复写入）
- [world-graph.ts:374-428](../../packages/world-graph/src/world-graph.ts#L374) `processEvent` 非原子：先 `eventLog.append`（L382）再改 Entity/Fact
- [world-graph.ts:413-425](../../packages/world-graph/src/world-graph.ts#L413) `Fact.create` 无幂等键检查

**修复方案**：commit.ts 加 try/catch 包裹写扩散循环，失败时清理 plan 缓存避免重复 commit。不引入真事务（world-graph SDK 不支持），只保证"失败不残留 plan + 错误冒泡 + 已写入脏数据可追溯"。

**修改文件**：`packages/scheduler/src/commit.ts`

**修改点**：包裹步骤 4-5 的写扩散循环

```typescript
// world-graph.ts 新增方法
/**
 * 更新单条 Fact 的 embedding（P0-5 修复，2026-07-27）
 *
 * commit.ts 写扩散后增量更新向量，避免全量 reembedAll 的性能开销。
 * 找不到 declarationId 对应的 Fact 时不抛错（兼容导入器遗留数据）。
 *
 * @param declarationId Fact 主键
 * @param embedding 512 维归一化向量
 *
 * TODO（P3 性能优化，子代理审查建议）：
 *   当前 `this.store.nodes.Fact.find()` 是全表扫描。Fact 表大时（>1000 条）
 *   每次 commit 都全表扫 N 次（N=state_changes 数）。
 *   初期保持简单跑数据，视性能决定是否用 SDK query() 建 declarationId 索引。
 */
async updateFactEmbedding(declarationId: string, embedding: number[]): Promise<void> {
  const facts = await this.store.nodes.Fact.find();
  const fact = facts.find((f: any) => f.declarationId === declarationId);
  if (!fact) return;  // 静默跳过（兼容性）
  await this.store.nodes.Fact.update(fact.id, {
    embedding: embedding as unknown as EmbeddingValue,
  });
}

/**
 * 更新单条 Entity 的 embedding（P0-5 修复，备用 API）
 *
 * Entity.summary 变化时调用。当前 commit.ts 不修改 summary，
 * 此方法预留给未来 updateEntitySummary 路径使用。
 */
async updateEntityEmbedding(entityId: string, embedding: number[]): Promise<void> {
  const entities = await this.store.nodes.Entity.find();
  const ent = entities.find(
    (e: any) => e.entityId === entityId && e.validTo === INFINITY,
  );
  if (!ent) return;
  await this.store.nodes.Entity.update(ent.id, {
    embedding: embedding as unknown as EmbeddingValue,
  });
}
```

参考 `src/planner-llm.ts` 的模式（pi-ai complete + validateToolCall + 重试）实现 `makeKnowledgeMapperLlmCaller`：

```typescript
// src/knowledge-mapper-llm.ts（新增文件）
import { complete, getModel, validateToolCall, Type } from "@earendil-works/pi-ai";
import type { Tool } from "@earendil-works/pi-ai";
import type { KnowledgeMapperLlmCaller } from "@pi/scheduler";
import { buildKnowledgeMapperSystemPrompt, buildKnowledgeMapperUserMessage } from "@pi/scheduler";

const MAX_NO_TOOL_RETRIES = 3;
const RETRY_DELAY_MS = 1000;

const knowledgeMapperSchema = Type.Object({
  mappings: Type.Array(Type.Object({
    knowledge: Type.String(),
    declarationId: Type.Union([Type.String(), Type.Null()]),
    confidence: Type.Number({ minimum: 0, maximum: 1 }),
  })),
});

const knowledgeMapperTool: Tool = {
  name: "knowledge_mapper",
  description: "把 knowledge_gained 自然语言映射到 declarationId。必须调用此工具一次提交结果。",
  parameters: knowledgeMapperSchema,
};

export function makeKnowledgeMapperLlmCaller(
  model: string,
  apiKey: string,
  provider: string = "deepseek",
): KnowledgeMapperLlmCaller {
  const tools: Tool[] = [knowledgeMapperTool];

  return async (characterId, knowledgeItems, candidates) => {
    const modelObj = getModel(provider as never, model as never);
    const systemPrompt = buildKnowledgeMapperSystemPrompt();
    const userMessage = buildKnowledgeMapperUserMessage(characterId, knowledgeItems, candidates);

    for (let attempt = 0; attempt < MAX_NO_TOOL_RETRIES; attempt++) {
      const msg = await complete(
        modelObj,
        {
          systemPrompt,
          messages: [{ role: "user", content: userMessage, timestamp: Date.now() }],
          tools,
        },
        {
          apiKey,
          maxTokens: 2000,
          temperature: 0.2, // 映射任务需要确定性，降低随机性
        },
      );

      if (msg.stopReason === "error" || msg.errorMessage) {
        throw new Error(`knowledgeMapper LLM 调用失败: ${msg.errorMessage ?? "unknown"}`);
      }

      const toolCall = msg.content.find((b) => b.type === "toolCall");
      if (!toolCall || toolCall.type !== "toolCall") {
        if (attempt < MAX_NO_TOOL_RETRIES - 1) {
          await new Promise((r) => setTimeout(r, RETRY_DELAY_MS));
          continue;
        }
        throw new Error(`LLM 未调用 knowledge_mapper 工具（重试 ${MAX_NO_TOOL_RETRIES} 次后仍失败）`);
      }

      const params = validateToolCall(tools, toolCall) as { mappings: unknown[] };
      const rawMappings = Array.isArray(params.mappings) ? params.mappings : [];
      return rawMappings.map((m) => {
        const raw = m as Record<string, unknown>;
        return {
          knowledge: typeof raw.knowledge === "string" ? raw.knowledge : "",
          declarationId: typeof raw.declarationId === "string" ? raw.declarationId : null,
          confidence: typeof raw.confidence === "number" ? raw.confidence : 0,
        };
      });
    }
    throw new Error("makeKnowledgeMapperLlmCaller: unreachable");
  };
}
```

**注**：`buildKnowledgeMapperSystemPrompt` 和 `buildKnowledgeMapperUserMessage` 由 `packages/scheduler/src/prompts.ts` 导出（见修改点 4）。需在 `packages/scheduler/src/index.ts` 的 exports 中追加这两个函数。

**置信度阈值**（统一为 0.5，与代码示例一致）：
- 0.5 以下：不写 Visibility（避免误映射污染）
- 0.5-0.8：写 Visibility，confidence 透传
- 0.8 以上：写 Visibility，confidence 透传
- **注**：初期保持 0.5 跑数据，观察误映射率后决定是否上调到 0.6（见第九节决策点 5）

**source 字段语义**：
- `"experienced"`：自盲修复（4.3 步，自己产出的 state_changes）
- `"informed"`：他盲修复（4.4 步，从他人学到的 knowledge_gained）
- `"witnessed"`：[character-view.ts:64](../../packages/world-graph/src/character-view.ts#L64) inferVisibility 用（基础设施关系推断）

**注**（⚠️ 子代理审查建议）：`VisibilityDeclaration.source` 在 [world-graph/src/types.ts:105](../../packages/world-graph/src/types.ts#L105) 是 `z.string()`（自由字符串），无需修改 schema。但建议同步更新该处注释，把 `rumor` 改为 `informed | experienced | witnessed | 自定义`，以反映实际使用值。

### 2.2 "=0" 的证据（共同特征）

1. **无分层**：全局约束（输出契约/引擎身份）与项目规则（三件套）与任务指令全部平铺拼接，无优先级结构。
2. **无示例**：所有子代理零 few-shot 示例——输出质量完全依赖工具 schema 与模型本能。
3. **无自检/纠错指令**：无"先规划再执行""检查是否符合规则""与已写正文衔接"等引导；角色一致性、前情引用等 G5-2 目标项完全未覆盖。
4. **无记忆/前情注入**：G5-1（记忆注入）未实施，SYSTEM.md 预留未用。
5. **无版本与评估**：提示词无版本管理、无效果基线（编排成功率/违规率无量化），优化无法度量。
6. **规则集模板单薄**：三件套模板仅 24/46/35 行，无结构（无章节/风格/人设分层约定）。

## 五、优化方向草案（调研后细化）

1. **分层提示词架构**：全局层（引擎身份/输出契约/提交约束）→ 项目层（规则集三件套）→ 任务层（各阶段指令）→ 角色层（角色卡）。各层职责单一、可独立迭代与版本化。
2. **结构化输出与示例**：基于现有 TypeBox 工具 schema 补 few-shot 示例 + 自检指令（如"产出前核对与规则集的一致性"）。
3. **一致性三件套**（对齐 G5-1/G5-2）：记忆注入（SYSTEM.md + memory.md）→ 前情引用 → 角色一致性约束。
4. **错误恢复**（对齐 G5-4）：子代理失败重试 + 提示词内降级指引。
5. **评估机制**：建立提示词版本表 + 效果基线（编排成功率 / 子代理 errorCount / render_check 违规数 / 正文锚点合规率），每次优化可回退、可比对。

## 一、需求原话与转述

> 用户原话："各个模块割裂，创作的时候看不到世界图，叙事的时候看不到世界图，叙事渲染完成了还要专门切换到小说页面进行查看结果。建议：将对话功能做成悬浮窗类型，可以在任意界面打开，对话。等等"
>
> 排期标注："排期（尚早，持续优化项目）"

**转述**：
1. **问题**：视图模块全页互斥，创作/叙事/结果查看三件事被拆散到不同页面——创作编排时看不到世界图状态，聊天叙事时看不到世界图，渲染完成后必须切到文件页才能看正文结果。
2. **方向建议**：把**对话功能做成悬浮窗**，任意界面可打开、可对话（悬浮于其他视图之上）。
3. **排期**：尚早，属于持续优化项目——仅记录方向，不排实施。

## 二、现状查证（2026-08-08）

- **全页互斥切换**：`app.js` 的 `renderShell()`（L297）渲染共享外壳（Logo/项目菜单/六视图导航/storyTime/搜索），但视图区 `<div id="view-root">`（L333）每次 `renderView()` 整体替换——graph/events/studio/files/debug/settings **同一时刻只存在一个视图**，无并置或悬浮。
- **能力分布**：
  - 对话 + 编排（plan/yolo）→ 独占 studio 页
  - 世界图可视化（含角色视角/信息差）→ 独占 graph 页
  - 正文结果 → 独占 files 页（编排完成后须经 J12 跳转查看）
- **shell 无全局对话入口**：无任何跨视图聊天气泡/面板。

**结论**：用户的"割裂"描述与实现一致——三件强关联的事情（对话驱动 → 世界状态反馈 → 正文产出）被拆到三个互斥页面。

## 三、设计方向草案（存档，不排期）

### 3.1 悬浮对话窗（用户建议的核心）

- 形态：悬浮按钮（右下角）+ 展开为**浮动面板/抽屉**，可跨任意视图打开；打开时不销毁当前视图（`#view-root` 保留），面板以 fixed 定位浮于其上。
- 与现有 studio 的关系（需决策）：studio 保留为**深度工作台**（编排结果面板/plan 审核/计划详情），悬浮窗提供**轻量对话**（口述、发指令、看流式回复）；或悬浮窗即完整对话能力，studio 收敛。
- 对话上下文保持：切视图不丢会话状态（会话由后端 `.pi/sessions/` 持久化，前端只需不重建视图）。

### 3.2 跨视图联动（"创作时看得到世界图"的最小实现路径）

| 联动 | 说明 | 依赖 |
|---|---|---|
| 对话中 @ 实体 → 图上定位 | 悬浮窗内 @ 提及命中实体时，若当前在 graph 页则高亮该实体（J7 已有跳转选中逻辑可复用） | 低 |
| 编排阶段实时可见 | **已改方向（2026-08-08 用户决策）**：阶段内容内联在聊天消息流（借鉴 ZCode 工具卡，见问题 1 记录 §五.6），悬浮窗即聊天——阶段卡片随对话自然可见，**无需独立面板**，本行从"悬浮窗附属组件"降级为"随对话自然获得" | 问题 1 实施后 |
| 渲染完成直达 | 章节生成后提供**非跳转**的浮层预览（读 chapterPath 内容浮窗展示），不必切 files 页 | 中 |
| storyTime 联动 | 悬浮对话上下文中的 storyTime 与外壳选择器同步（已是全局态，天然可用） | 低 |

### 3.3 与既有跳转逻辑的关系

现有 J1-J14 跳转规则（frontend-requirements §3.2）是"全页切换"模型；悬浮窗是"叠加"模型——两者并存时需约定：悬浮窗打开不触发 navigate；深度操作（plan 审核/文件编辑）仍走全页跳转。

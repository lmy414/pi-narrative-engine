🖋️ narrative-engine 项目全景图

叙事引擎 —— 面向小说创作的「世界图 + AI 编排」引擎 ｜ 数据截至 2026-08-01
这是什么？ 一个帮助 AI 写小说的引擎：用「世界图」记录故事里谁是谁、发生过什么、谁知道了什么；用「编排器」让多个 AI 子代理（策划/角色/推理/渲染）像剧组一样协作推进剧情，最后把剧情写成章节正文。当前正在从「依赖 PI 扩展」转型为「基于 PI SDK 的独立应用」。

🔀 数据流（目标形态：从用户话到章节正文）

              │  AI 判断意图（闲聊/写设定/推进剧情）
              ▼
         scheduler_dispatch（事件派发）
              ▼
        ┌─ 编排器 Orchestrator ────────────────────────┐
        │ ① planner 子代理：查世界图 → 定检索策略        │
        │ ② 角色子代理 ×N：扮演角色 → 输出行动/心理      │
        │ ③ 可见推理子代理：推理 → 写世界图（状态扩散）   │
        │ ④ 渲染器子代理：读章节 → 写正文                │
        └──────────────────────────────────────────────┘
              ▼
        世界图（world.db）    章节文件（正文）
        角色状态/关系/可见性     正文

🔗 scheduler 旧流水线

调度器核心：plan（10 步线性流水线）/ commit / retrieve / cache。设计上是编排器的「前任」，当前仍被 PI 扩展工具使用。

packages/scheduler/src/{plan,commit,retrieve,cache,...}.ts

🎭 role-pool 被新编排器替代

角色池批处理演绎：把角色卡+动态事实 → LLM → 结构化行动。新编排器改为每角色一个 Agent 子代理。

packages/role-pool/src/{role-pool,transforms,prompts}.ts

✍️ renderer 在用

渲染器：LLM 生成正文 + 章节文件 IO（锚点追加/修改/插入），供渲染器子代理使用。

packages/renderer/src/{renderer,chapter-io,prompts}.ts

📥 novel-importer 在用

小说导入器：EPUB/文本 → 世界图实体/事件/关系 + 章节文件。多阶段流水线。

packages/novel-importer/src/{pipeline,stages,write}.ts

🛠️ admin 在用

管理模块：文件编辑器、规则集、novel.json、应用配置、更新检查、embedder 状态。

packages/admin/src/{files,rulesets,updater,...}.ts
